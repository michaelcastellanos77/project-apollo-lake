# Experiment 008 — Qwen2.5-0.5B-Instruct Evaluation

**Date:** 2026-09-17  
**Phase:** Phase 2 — LLM research and selection  
**Status:** Completed as an initial candidate evaluation; model not selected as final assistant model

## Objective

Evaluate an extremely small bilingual LLM on the Apollo Lake target hardware before moving to heavier candidates. The evaluation focused first on linguistic suitability and then on a quick CPU/Vulkan acceleration check.

## Hardware / environment

- Lenovo IdeaPad 120S-11IAP
- Intel Celeron N3350 — 2 cores / 2 threads
- 4 GB installed RAM (~3.66 GiB visible to Linux)
- Intel HD Graphics 500 (APL 2)
- Alpine Linux 3.24.1, installed persistently to internal eMMC
- Kernel: 6.18.35-0-lts
- Internal model storage: `/opt/apollo-lake/models/qwen2.5-0.5b/`
- Inference runtime: llama.cpp 0.0.9564-r0
- Model: Qwen2.5-0.5B-Instruct-GGUF, Q4_K_M
- Model file size: 468.6 MiB

## Methodology

1. Install the official Alpine llama.cpp package and verify `llama-cli` is available.
2. Download the Qwen2.5-0.5B-Instruct Q4_K_M GGUF to the internal eMMC.
3. Verify the model file exists and can be loaded by llama.cpp.
4. Use llama.cpp conversation mode (`-cnv`) so the model's GGUF chat template is used rather than testing the Instruct model as a raw completion.
5. Use 2 CPU threads (`-t 2`) for CPU tests because the N3350 exposes 2 threads.
6. First establish basic English and Simplified Chinese generation.
7. Test English→Chinese translation, Chinese→English translation, and mixed English/Chinese conversation.
8. Record llama.cpp's reported prompt-processing and generation throughput for each run. Generation tokens/s is the main conversational-performance metric; prompt tokens/s measures input processing speed.
9. Install Alpine's Vulkan stack and Mesa Intel Vulkan driver only after CPU/linguistic testing.
10. Verify the Intel HD Graphics 500 through `vulkaninfo` and verify that llama.cpp exposes `Vulkan0`.
11. Attempt a quick Vulkan inference comparison using the same Q4_K_M model. `-ngl 99` was attempted for extensive offload and crashed with a segmentation fault; a subsequent `-ngl 1` partial-offload test completed.
12. Do not treat the Vulkan result as a rigorous benchmark because the GPU tests were diagnostic/quick comparisons rather than a fully controlled benchmark suite.

## Model / runtime setup

### CPU-only inference

Initial command structure:

```sh
llama-cli \
  -m /opt/apollo-lake/models/qwen2.5-0.5b/qwen2.5-0.5b-instruct-q4_k_m.gguf \
  -t 2 \
  -n 128 \
  -cnv
```

Conversation mode was important: raw `-p` completion tests initially caused the model to respond incorrectly to Chinese instructions. Using conversation mode produced a sensible Chinese self-introduction and was therefore used for the functional bilingual evaluation.

### Vulkan setup

Installed:

- `llama.cpp-vulkan`
- `vulkan-loader`
- `mesa-vulkan-intel`
- `vulkan-tools`

Vulkan verification identified:

- GPU: Intel(R) HD Graphics 500 (APL 2)
- vendor ID: `0x8086`
- device ID: `0x5a85`
- driver: Intel open-source Mesa driver
- Mesa: 26.1.6

llama.cpp then reported:

```text
Available devices:
  BLAS: OpenBLAS (0 MiB, 0 MiB free)
  Vulkan0: Intel(R) HD Graphics 500 (APL 2) (1875 MiB, 1688 MiB free)
```

## Functional results

### English generation

Basic English smoke test succeeded.

Observed generation: **2.6 t/s**  
Observed prompt processing: not retained as a formal benchmark value from the first smoke test.

### Simplified Chinese generation

Conversation-mode Chinese self-introduction succeeded and was coherent.

Observed:

- Prompt: **11.4 t/s**
- Generation: **2.5 t/s**

### English → Chinese

Prompt:

> Please translate the following sentence into natural Simplified Chinese: "I am studying mathematics at university because I enjoy solving difficult problems."

Output was understandable but somewhat unnatural:

> 我大学学习数学，因为我觉得解决困难的问题很有趣。

Observed:

- Prompt: **14.7 t/s**
- Generation: **2.5 t/s**

### Chinese → English

Prompt:

> 请把下面这句话翻译成自然的英文：“我今天下午要去图书馆学习，因为明天有数学考试。”

Output was semantically understandable but grammatically awkward:

> Today afternoon, I'm going to the library to learn because I'm going to have the math exam tomorrow.

Observed:

- Prompt: **6.8 t/s**
- Generation: **2.4 t/s**

### Mixed English/Chinese conversation

Prompt:

> 我今天在 UCL 上了一整天的 maths 课，现在感觉有点 tired。你觉得我今晚应该继续学习，还是早点休息？

Instead of answering the question, the model translated the question into English. Repeated clarification and repetition of the question did not make it answer the intended question; it eventually returned variants of `您的问题是什么？`.

Observed runs included:

- Prompt: **6.7 t/s**, Generation: **2.2 t/s**
- Prompt: **5.8 t/s**, Generation: **2.1 t/s**
- Prompt: **2.8 t/s**, Generation: **2.3 t/s** during a clarification turn
- Prompt: **2.6 t/s**, Generation: **2.3 t/s** during another clarification turn
- Prompt: **4.9 t/s**, Generation: **2.4 t/s** on a repeated mixed-language question

## Performance summary

CPU-only generation across the functional tests was approximately **2.1–2.6 t/s**, with most substantive responses around **2.2–2.5 t/s**.

Prompt processing varied substantially with prompt length/content, approximately **2.6–15.9 t/s** across the recorded tests. Prompt throughput is not directly comparable between prompts of different lengths and should not be treated as a single model speed figure.

## Vulkan / iGPU results

The persistent Alpine installation successfully exposed the Intel HD Graphics 500 through Vulkan and llama.cpp detected it as `Vulkan0`.

An extensive offload test:

```sh
-ngl 99
```

resulted in:

```text
Segmentation fault
```

Therefore no performance value was recorded for that run.

A partial-offload test with:

```sh
-ngl 1
```

completed successfully and produced:

- Prompt: **6.5 t/s**
- Generation: **2.2 t/s**

This was a quick diagnostic comparison rather than a controlled CPU-vs-GPU benchmark because the prompt differed from the CPU tests and only one layer was offloaded. It therefore does **not** establish that the iGPU is faster or slower than CPU inference. It does establish that limited Vulkan offloading can execute successfully, while extensive offloading (`-ngl 99`) crashed in this configuration.

## Assessment

Qwen2.5-0.5B-Instruct is a useful low-resource baseline:

- Very small model footprint (~469 MiB Q4_K_M)
- Runs successfully on the N3350 CPU
- Produces coherent English
- Produces coherent Simplified Chinese in conversation mode
- Performs basic English↔Chinese translation, but with noticeably weak naturalness
- Mixed English/Chinese conversational instruction following was not reliable in the tested prompts
- CPU generation is around 2.1–2.5 t/s for most observed runs
- Vulkan is available on the HD 500, but extensive llama.cpp Vulkan offload crashed and limited offload did not demonstrate a clear advantage

**Selection status:** Not selected as the final Apollo Lake LLM at this stage. Retained as a baseline/reference model for comparison with heavier candidates.

## Reproducibility notes

The first Chinese tests used raw `-p` completion mode and produced repeated explanations of `llama-cli` rather than answering the Chinese instruction. This was traced to the session being used in the wrong mode: after a generation, the `>` prompt was llama.cpp's interactive prompt, not the Alpine shell. The final functional tests therefore used explicit llama.cpp conversation mode and the model's chat template.

The Vulkan environment required `mesa-vulkan-intel` in addition to the llama.cpp Vulkan backend and Vulkan loader. `vulkaninfo --summary` initially reported `Found no drivers`; after installing the Mesa Intel Vulkan driver, it correctly identified the HD Graphics 500.
