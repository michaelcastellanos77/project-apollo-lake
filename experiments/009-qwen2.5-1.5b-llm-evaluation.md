# Experiment 009 — Qwen2.5-1.5B-Instruct Evaluation

**Date:** 2026-09-17  
**Phase:** Phase 2 — LLM research and selection  
**Status:** Completed candidate evaluation; current leading candidate, not yet final selection

## Objective

Evaluate Qwen2.5-1.5B-Instruct as the first heavier Apollo Lake candidate. The experiment tested linguistic suitability first, then CPU performance and governor behaviour, followed by persistent Vulkan/iGPU inference.

## Hardware / environment

- Lenovo IdeaPad 120S-11IAP
- Intel Celeron N3350 — 2 cores / 2 threads
- 4 GB installed RAM (~3.7 GiB visible to Linux)
- Intel HD Graphics 500 (APL 2)
- Alpine Linux 3.24.x, installed persistently to internal eMMC
- Kernel: 6.18.35-0-lts
- Internal model storage: `/opt/apollo-lake/models/qwen2.5-1.5b/`
- Inference runtime: llama.cpp 0.0.9564-r0
- Model: Qwen2.5-1.5B-Instruct-GGUF, Q4_K_M
- Model file size: 1.0 GiB on disk
- CPU tests: 2 threads
- Swap: explicitly disabled for the benchmark session

## Important environment correction

An earlier Qwen2.5-1.5B download initially occurred while the machine was booted into Alpine's temporary tmpfs root. That environment had only a 1.8 GiB RAM-backed `/`, causing the first download to fail with `No space left on device` at approximately 934 MiB.

The partial file was removed and the machine was rebooted into the persistent Alpine installation. The persistent root was verified as:

```text
/dev/mmcblk0p3 on / type ext4 (rw,relatime)
```

The persistent installation had approximately 22.4 GiB free. The model was then downloaded successfully to the internal eMMC.

This experiment's performance results were therefore conducted on the persistent Alpine environment, not the temporary tmpfs environment.

## Baseline memory state

Before model testing:

```text
Mem:  3.7G total, 151.7M used, 3.5G free, 3.4G available
Swap: 0 total, 0 used, 0 available
```

Swap was disabled with `swapoff -a` so that model inference could not silently spill memory pages to non-volatile storage during controlled performance testing.

## Methodology

1. Boot persistent Alpine from internal eMMC and verify `/` is the eMMC ext4 filesystem.
2. Disable swap for controlled inference measurements.
3. Verify the model file is present on persistent storage.
4. Verify llama.cpp 0.0.9564-r0 can load and execute the model.
5. Use llama.cpp conversation mode (`-cnv`) for Instruct-model functional testing.
6. Use 2 CPU threads (`-t 2`) for normal CPU tests because the N3350 exposes 2 threads.
7. Test English generation.
8. Test Simplified Chinese generation.
9. Test English→Chinese translation.
10. Test Chinese→English translation.
11. Test mixed English/Chinese conversational interaction.
12. Record prompt-processing and generation throughput. Generation tokens/s is the primary conversational speed metric; prompt tokens/s is recorded separately because it varies with prompt length/content.
13. Test CPU governor behaviour by comparing `schedutil` and `performance` using the same English prompt.
14. Restore `schedutil` after the governor experiment.
15. Install and verify the Vulkan userspace stack on the persistent Alpine installation.
16. Verify Vulkan independently with `vulkaninfo --summary`.
17. Verify llama.cpp exposes the Intel HD Graphics 500 as `Vulkan0`.
18. Run Qwen2.5-1.5B with extensive Vulkan offload (`-ngl 99`) using the same English prompt.
19. Repeat the English Vulkan test once for confirmation.
20. Repeat the Chinese, translation and mixed-language tests under Vulkan.
21. Treat the CPU/Vulkan comparison as a strong observed result but not a full statistical benchmark suite because the tests were individual interactive runs rather than repeated controlled trials.

## CPU linguistic results

### English

Prompt:

> Hello! Introduce yourself briefly and explain what kinds of things you can help me with.

Result: coherent, relevant English response; direct instruction following.

Observed:

- Prompt: **4.4 t/s**
- Generation: **1.5 t/s**

### Simplified Chinese

Prompt:

> 请用自然、流畅的简体中文介绍一下你自己，并说明你可以帮助用户做哪些事情。

Result: coherent and natural Simplified Chinese response; direct instruction following.

Observed:

- Prompt: **1.8 t/s**
- Generation: **1.4 t/s**

### English → Chinese

Prompt:

> Please translate the following sentence into natural Simplified Chinese: "I am studying mathematics at university because I enjoy solving difficult problems."

Result:

> I am studying mathematics at university because I enjoy solving difficult problems. (我正在大学学习数学，因为我喜欢解决难题。)

The Chinese translation itself was good, but the model unnecessarily repeated the English source.

Observed:

- Prompt: **2.6 t/s**
- Generation: **1.2 t/s**

### Chinese → English

Prompt:

> 请把下面这句话翻译成自然的英文：“我今天下午要去图书馆学习，因为明天有数学考试。”

Result:

> I am going to study at the library today because there is an math exam tomorrow.

The meaning was preserved, but the response contained a grammatical error (`an math` rather than `a math`) and omitted `this afternoon`.

Observed:

- Prompt: **2.3 t/s**
- Generation: **1.2 t/s**

### Mixed English/Chinese conversation

Prompt:

> 我今天在 UCL 上了一整天的 maths 课，现在感觉有点 tired。你觉得我今晚应该继续学习，还是早点休息？

Initial result: the model translated the mixed-language question into English instead of answering it.

After the clarification:

> Oh, please answer 真正的问题

The model recovered and gave a coherent answer to the underlying question.

Observed:

- Initial prompt: **2.3 t/s prompt, 1.2 t/s generation**
- Clarification: **1.5 t/s prompt, 1.2 t/s generation**

Assessment: **partial pass** — initial mixed-language conversational instruction following was unreliable, but the model successfully recovered after explicit clarification.

## Additional Chinese factual-reliability test

A separate prompt asked for a simple Chinese chronological summary of *Romance of the Three Kingdoms* up to Guan Yu's death.

The model produced fluent-looking Chinese but included major factual/chronological errors, including describing Guan Yu as Liu Bei's adopted son and placing events after Liu Bei's death even though Guan Yu died earlier.

Assessment: **fail for factual reliability on this tested historical-summary prompt**.

This result is important because fluent Chinese output should not be treated as evidence of reliable factual knowledge.

## CPU frequency / governor investigation

`cpupower frequency-info` reported:

```text
Driver: intel_cpufreq
Hardware limits: 800 MHz - 2.40 GHz
Available governors: ondemand performance schedutil
Current governor: schedutil
Boost: Supported: yes / Active: yes
```

An instantaneous kernel-asserted frequency was approximately 2.29 GHz before the governor test.

The governor was temporarily changed to `performance` and the same English prompt was run again.

Results:

| Governor | Generation |
|---|---:|
| `schedutil` | **1.5 t/s** |
| `performance` | **1.5 t/s** |

The observed result did not show a generation-speed improvement from changing the governor. The governor was restored to `schedutil` after the test.

The previous Phase 1 thermal test had observed a maximum of approximately 54°C during a short 2-core sustained load, compared with a thermal trip point of 105.05°C. Therefore there was no evidence that thermal throttling was limiting this short inference test.

## CPU vs Vulkan summary

Observed generation throughput:

| Test | CPU | Vulkan |
|---|---:|---:|
| English | 1.5 t/s | **2.4–2.5 t/s** |
| Chinese | 1.4 t/s | **2.4 t/s** |
| English→Chinese | 1.2 t/s | **2.4 t/s** |
| Chinese→English | 1.2 t/s | **2.5 t/s** |
| Mixed conversation | 1.2 t/s | **2.3–2.4 t/s** |

Across these observed runs, Vulkan approximately increased generation throughput from the CPU range of **1.2–1.5 t/s** to **2.3–2.5 t/s**. The English confirmation runs specifically increased from 1.5 t/s CPU to 2.4–2.5 t/s Vulkan.

This is strong evidence that the Intel HD Graphics 500 can provide useful llama.cpp Vulkan acceleration for this model/configuration. It is still not a statistically rigorous benchmark because each workload was tested only once or twice.

## Assessment

Qwen2.5-1.5B-Instruct is currently the **leading Apollo Lake candidate** among the models actually evaluated.

Strengths:

- Fits and runs with swap disabled in the ~3.7 GiB physical-RAM environment.
- Strong English generation in the tested prompt.
- Strong Simplified Chinese generation in the tested prompt.
- Bidirectional translation is usable, with some naturalness/instruction-format issues.
- Mixed-language conversation can recover after clarification.
- Vulkan `-ngl 99` works in the persistent environment.
- Vulkan generation of approximately **2.3–2.5 t/s** is substantially faster than CPU-only generation of approximately **1.2–1.5 t/s**.

Weaknesses / open issues:

- Does not yet meet the project's later performance target of **3.5 t/s minimum generation** in the observed Vulkan configuration.
- Does not yet have a formal prompt-throughput benchmark because the recorded prompt speeds vary with prompt length/content.
- Mixed-language input initially triggered translation instead of answering.
- The tested Three Kingdoms factual-summary prompt produced major factual errors despite fluent Chinese output.
- More candidates must be evaluated before final selection.

**Selection status:** Current leader, but not final selection.

## Reproducibility / interpretation notes

- The model itself is unchanged between CPU and Vulkan tests; only the inference backend/device was changed.
- Vulkan does not make the model intrinsically more capable; differences in wording between individual runs are normal generation variation and should not be attributed to Vulkan.
- Generation tokens/s is the primary conversational throughput metric for Apollo Lake.
- Prompt tokens/s is retained as a secondary metric but should not be compared directly across prompts of different lengths.
- The 1.5B model's current Vulkan throughput is an observed result, not a guaranteed sustained 30-minute throughput figure.
- Swap was disabled to prevent inference from silently using non-volatile storage during the controlled benchmark.
